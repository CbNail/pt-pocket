# App 与 NAS 后端职责边界（本轮改造依据）

本文件回答一个问题：**每块能力的数据从哪来、App 做什么、NAS 后端做什么。**
它同时是本轮「站点数据面板 / 下载器任务 / 搜索实时展示 / 签到 / 我的数据 / 养老进度 / 监护室」
几项改造的实现依据，配套接口见 [`api-contract.md`](api-contract.md)。

## 0. 总则

| 侧 | 职责 |
| --- | --- |
| 移动端（Flutter） | 交互与展示、表单与参数、本地缓存与凭据保管、**可达性探测**、把结果按统一字段渲染、失败态与空态的呈现 |
| NAS 后端 | 站点页面与 API 的抓取与解析、下载器协议调用、定时任务与补签、跨站聚合与归一化、历史快照与趋势、等级/保号规则匹配、凭据加密存储 |

三条硬性约束：

1. **App 不直连数据库 / Redis，也不在页面里实现站点 HTTP 逻辑**（规格书 §7.1）。
2. **后端未实现时，App 只能显示空态或「数据未提供」，不得用占位数字伪造成站点数据。**
3. 任何写操作都带幂等键；站点凭据只在后端落地，App 侧只保存「已配置」这一状态位。

## 2. 参考实现要点（本轮对齐依据）

参考仓库：[`jxxghp/MoviePilot-Plugins`](https://github.com/jxxghp/MoviePilot-Plugins)、
[`pt-plugins/PT-depiler`](https://github.com/pt-plugins/PT-depiler)。

本轮实际读取的参考实现（逐条对照）：

| 需求里提到的名字 | 参考仓库中的实际实现 |
| --- | --- |
| 站点自动签到 | `plugins/autosignin`（`sites/` 下每站一个 `_ISiteSigninHandler`） |
| 站点数据统计 | `plugins/sitestatistic`（`siteuserinfo/` 下按框架解析用户页；另含 `plugins/sitestatistic` 同名 V1 副本） |
| PT 数据统计 | `plugins.v2/ptdatastatistics`（统计累计/每日上传下载，提供历史、养老进度与通知） |
| 保种 / 做种统计、时魔估算 | `plugins.v3/seedstats`（站点保种统计） |
| 连接数 / 客户端 / 服务器筛选 | `plugins.v3/siteuserdetail`（站点用户详情采集） |
| 站点数据刷新 | `plugins/sitestatistic` 的定时/手动刷新（`refresh_by_domain` / `refresh_all_site_data`）、`plugins/autosignin` 的「立即运行一次」 |
| 站点 Cookie / UA 刷新 | `plugins/siterefresh`（浏览器模拟登录站点获取 Cookie 和 UA） |
| H&R / 保种契约（考核） | `plugins/contractcheck`（契约检查，定时检查保种契约达成情况）、`plugins.v3/hrblocker` |
| 搜索实时展示 | PT-depiler 桌面端搜索页（`SearchStatusDialog` 状态弹窗 + 结果表按站点增量追加） |

> 「PT 保号状态」「站点考核状态」「PT 监护室」在参考仓库里**没有同名插件**：保号能力由
> `plugins.v2/ptdatastatistics` 的养老进度（等级路线、下一等级条件、保号目标、任选条件）承担；
> 考核 / H&R 由 `plugins/contractcheck`（保种契约达成）与 `plugins.v3/hrblocker` 承担；
> 站点数据由 `plugins/sitestatistic` 承担；监护室沿用本品规格书 §5.9 的事件巡检口径。
> 本文件与规格书都按这个映射描述，不虚构不存在的插件能力。

- **站点自动签到**（`plugins/autosignin`）：每站一个签到处理器，接口为
  `match(url)` + `signin(site_info) -> (bool, message)`；由 cron 调度，支持「立即运行一次」，
  自动过滤已删除站点；结果只有成功/失败与原因两类语义。
  插件把站点分成两类配置——**签到站点**（`sign_sites`）与**仅模拟登录站点**（`login_sites`）：
  有些站不定义签到，只能靠模拟登录维持活跃。本轮移动端按同一口径给出
  「签到 + 模拟登录 / 仅签到 / 仅模拟登录」三种下发方式（`SignInMode`），结果里标注本次动作
  （`SignInAction`），并原样保留插件的提示——**程序登录/签到不一定被站点计为用户活跃**
  （插件注释举了馒头的例子），不做「提示成功就不会掉号」的暗示。
- **PT 数据统计**（`plugins.v2/ptdatastatistics`）：数据源仅为后端已保存的站点用户数据，
  不抓站点、不读下载器；当日 = 当日累计 − 前一自然日累计，**缺少前一天快照时显示「基线不足」**；
  累计值下降时负增量按 0 处理；养老进度用「等级路线 + 下一等级条件 + 保号目标」表达，
  任选条件按**满足任一项**计算；后端未提供的指标（如发布数、平均做种时间）明确显示「数据未提供」。
  本轮落地口径：`todayUploadedBytes/todayDownloadedBytes + todayBaselineAvailable`（缺基线一律
  显示「基线不足」，不拿 0 冒充）、`nextClass/nextClassRequirement`、
  `policy.alternatives + policy.satisfiedAlternative`（并标出当前命中的那项）。
- **站点保种统计**（`plugins.v3/seedstats`）：按 tracker 把下载器任务归属到站点，
  统计做种/暂停/其他与辅种；时魔为**插件估算**（需显式标注，不等于站点官方时魔）；
  数据过期、零做种、tracker 未归属、已删除站点残留都在页面顶部告警；全程只读。
- **站点用户详情采集**（`plugins.v3/siteuserdetail`）：输出两个平铺列表——BT 客户端列表与
  下载中种子列表，**分组聚合交给调用方**；采集有 uid 缓存、请求上限、同站间隔与站点并发限制。
- **搜索实时展示**（PT-depiler 桌面端）：边搜边出——顶部显示「已接收 N 条结果，搜索仍在进行」，
  工具栏含暂停/停止、站点筛选与过滤，结果表按站点分组增量追加。

## 3. 本轮需要补的字段（App 侧模型）

现有字段（`lib/core/models/status_models.dart` 的 `SiteStats`）：上传、下载、分享率、魔力、
做种数、下载中数量、加入时间、等级、今日签到、连续签到、保号状态与进度。

本轮已补：**综合时魔**、**H&R 情况**、**邮件未读数**、**邀请数**、**连接数（BT 客户端）**、
**刷新时间与刷新状态（四态）**、**今日上传/下载与基线标记**、**等级路线**、**任选条件**、
**保种契约（H&R / 契约检查）达成**。
所有新字段一律「缺省即未提供」，不填 0 冒充；需要区分「0」与「无数据」的地方另给布尔标记
（如 `todayBaselineAvailable` / `contractMet` 的可空）。

「保种契约」与「保号进度」是两套口径，页面上分开呈现：前者看未完成的契约项数量（`hrCount`），
后者看等级与分享率等保号条件。

## 4. 站点刷新状态口径

面板筛选用的四态由后端给出，App 只渲染：

| 状态 | 判定 |
| --- | --- |
| 已刷新 | 本次刷新成功且数据时间在阈值内（参考 seedstats 默认 24 小时） |
| 未刷新 | 从未成功刷新，或上一次刷新已超过阈值 |
| 失败 | 最近一次刷新失败，`err_msg` 有具体原因 |
| 未登录 | 凭据缺失/失效，需要重新登录或导入 Cookie |

## 5. 建议新增的后端接口（供实现对齐）

| 方法 / 路径 | 用途 |
| --- | --- |
| `GET /api/v1/sites/{id}/stat` | 单站数据面板字段（含刷新状态、时魔、H&R、邮件、邀请、连接数） |
| `POST /api/v1/sites/{id}/refresh`、`POST /api/v1/sites/refresh` | 单站 / 全部刷新 |
| `GET /api/v1/sites/{id}/clients` | BT 客户端列表（服务器筛选数据源） |
| `GET /api/v1/sites/{id}/torrents` | 该站下载中种子（含促销标签） |
| `GET /api/v1/stats/overview?range=day\|week\|month` | 我的数据与统计趋势 |
| `GET /api/v1/care/plan` | 等级路线、下一等级条件、保号目标与任选条件 |
| `GET /api/v1/seedstats` | 按站点汇总的做种/辅种/体积/时魔估算 |
| `GET /api/v1/downloaders/{id}/tasks`（扩展参数） | 任务页需要的排序、状态、分类、标签、路径、服务器筛选 |

> 现有契约（搜索、推送、任务、个人数据、监护事件、签到）见 [`api-contract.md`](api-contract.md)；
> 本轮新增接口在实现落地后同步进契约文件。
