### 0.3 术语

- **PT 站点：** 提供种子发布、下载、做种统计和用户等级体系的私人 Tracker 网站。
- **站点适配器（Site Adapter）：** 将各站点不同的登录、搜索、详情、用户数据和签到接口封装为统一能力。
- **下载器（Downloader）：** qBittorrent、Transmission 等实际接收种子任务并下载的服务。
- **MP：** MoviePilot 实例。首期优先适配 V2，架构上隔离 V3 适配器。
- **Guardian / 监护室：** 对 PT 站点可用性、风险、站庆等信息进行汇总的外部或自建监控服务。
- **内外网双链路：** 同一 NAS 服务配置 LAN 地址和 WAN（Lucky 反代）地址，客户端优先使用可用的内网地址。

## 1. 产品概述

### 1.1 产品定位

PT Pocket 是一个面向个人 PT 用户的自托管移动管理中枢。用户通过 HarmonyOS 原生 App 或 Android 兼容客户端管理 PT 站点、聚合检索种子、查看 PT 账号与保种情况、监控站点风险，并把选中的种子推送到一个或多个下载器。NAS 负责长期运行的站点适配、搜索聚合、任务调度、数据快照和通知任务；手机负责交互、展示、确认和必要的安全凭据交互。

产品不以“把所有 PT 站点网页搬到手机里”为目标，而是把重复、分散的 PT 管理操作收敛为统一工作流，同时保留每个站点的规则差异和能力差异。

### 1.2 产品目标

1. 在一个 App 内维护多个 PT 站点和多个下载器，不再逐个登录网页查找。
2. 搜索体验接近 PT-depiler：多站并发、结果归一、去重、排序、详情和快捷推送。
3. 让用户快速看清站点状态、账号数据、保种义务和风险事件。
4. 把可安全自动化的重复操作交给 NAS 定时执行，并保留日志、失败原因和人工介入入口。
5. 支持 NAS 内网直连与 Lucky 外网反代自动切换，避免用户手动切换地址。
6. 凭据加密、最小化暴露、可备份恢复；App 和服务端升级时尽可能继承既有配置。

### 1.3 非目标 / 边界

- 不提供 PT 资源转载、公共索引、账号交易或站点注册服务。
- 不承诺所有 PT 站点都能自动化；每个站点必须基于明确适配能力和站点规则启用。
- 不绕过验证码、二次验证、访问频率限制、反爬保护或站点权限控制。遇到此类交互时转为人工完成。
- 不把 App 当作下载器本身；文件传输仍由 qBittorrent、Transmission 等下载器承担。
- 不把 NAS 暴露为公开多租户 SaaS。首期为单用户自托管，接口设计可为未来多设备扩展，但不为多租户引入不必要复杂度。

### 1.4 已确认的产品决策

| 项目 | 已确认方案 |
|---|---|

### 1.6 基于现有设备的部署结论

1. **计算与存储分离。** PT Pocket API、Worker、Scheduler、PostgreSQL 和 Redis 默认运行在 PVE 上的 Debian 13 VM；TS-451D 作为 NFS 存储与备份目的地。
2. **数据库不放在 NFS。** PostgreSQL 数据目录和 Redis 持久化目录使用 PVE VM 本地 SSD 虚拟磁盘；NFS 只用于备份、导出文件和用户指定的大文件共享。
3. **不要把 Docker 直接装进 PVE 宿主系统作为首选。** PVE 负责虚拟化生命周期；Docker 运行在独立 Debian VM，便于快照、备份、升级和故障隔离。
4. **TS-451D 不承担重型搜索并发。** 它可以运行轻量容器或备用服务，但不建议同时承担 PostgreSQL、Redis、多个站点 Worker 和 MoviePilot 等主要负载。
5. **HarmonyOS 采用双轨兼容策略。** 现有 Flutter Android 代码先保留；Mate 70 Pro+ 上先进行 APK / 卓易通安装与关键插件实测。同时建立 ArkTS / ArkUI 原生端验证工程，作为长期稳定的鸿蒙交付路径。
6. **PVE 资源配置暂按建议值设计。** 由于自组主机 CPU、内存和存储尚未提供，VM 配额是初始建议，不作为已确认的硬件事实。

### 2.4.1 鸿蒙设备兼容性判定

当前 ZIP 是 Flutter Android 工程，构建产物是 APK，不是 HarmonyOS 原生 HAP。用户主力设备为 Mate 70 Pro+ / HarmonyOS 6.1.0，因此“Android APK 能否安装”与“应用是否具备鸿蒙原生体验”必须分开验收。

- 华为官方面向 HarmonyOS 5 及以上的安装说明提到，互联网下载的安装包是否支持安装，应以卓易通实际支持情况为准。由此不能承诺任意 Android APK、插件和系统 API 在 Mate 70 Pro+ 上完整运行。
- 鸿蒙原生应用的官方开发路径为 ArkTS + ArkUI，采用 Stage 模型；应用由 HAP / APP 形态构建，开发和调试使用 DevEco Studio。
- Stage 模型对后台进程有系统治理，应用不能假设能像常驻 Android Service 一样无限期驻留。因此站点巡检、定时签到、搜索调度等必须由 NAS 执行，手机仅接收结果和通知。
- 第一阶段在 Mate 70 Pro+ 上建立兼容性测试矩阵：安装、启动、Dio/HTTP、Secure Storage、WebView、系统分享、文件选择、通知、后台恢复、网络切换、字体和手势。任一关键插件缺失时，不应强行用 APK 兼容层作为唯一正式方案。
- 原生鸿蒙端与 Flutter 端共享后端 OpenAPI、数据模型、错误码、设计令牌和验收用例；不要求两端共享 UI 源码。

## 3. 用户、场景与核心体验

### 3.1 目标用户

首期面向有 NAS、自建下载器和多个 PT 站点的个人用户。用户理解基本 PT 概念，但不希望每天打开多个站点、下载器和监控网站重复操作。

### 3.2 核心使用场景

**场景 A：发现并下载资源**  
用户打开搜索，输入片名或关键词；App 将请求交给 NAS，NAS 并行查询启用的站点 / MP；结果逐步出现并去重。用户点开详情，查看站点、大小、做种人数、下载人数、促销、发布时间等；选择目标下载器和路径后推送。长按可直接快速推送到默认目标，左滑可收藏或发起下载。

**场景 B：日常站点巡检**  
用户打开首页，看到站点在线概况、风险告警、即将到来的站庆、12 个重点站点的收集进度和最近自动化执行结果。点击异常站点可查看最近探测时间、连续失败次数、数据来源和建议操作。

**场景 C：保号 / 养老管理**  
用户为某站点设置保号目标、周期和提醒阈值；系统从站点支持的数据中读取上传、下载、做种时间或魔力值等指标，展示距离目标还差多少。无法自动获取的指标允许手动录入，并标注数据更新时间和来源。

**场景 D：外出访问**  
手机不在家庭 Wi-Fi 时，自动切换到 Lucky 反代 WAN；回到家后优先切换到 LAN。设置页可查看本次实际链路，并可手动强制内网或外网进行排障。

**场景 E：签到及失败处理**  
用户为支持且允许自动签到的站点开启任务，系统按站点时区和规则执行；失败时按安全策略有限重试。遇到验证码、二次验证或风控挑战时停止自动化并推送人工处理提示，不尝试绕过。

### 3.3 产品体验原则

- **信息先行：** 首页优先展示状态、待处理事项和可执行动作，不堆砌长表格。
- **渐进披露：** 搜索列表只展示决策所需摘要，详情再展示完整字段。
- **结果透明：** 每个数据点标明来源、更新时间、失败状态；不能把“未知”伪装成“正常”。
- **动作可撤回或确认：** 删除下载任务、替换凭据、覆盖配置、执行高影响自动化必须确认。
- **失败可解释：** 网络、鉴权、限流、站点结构变化和外部服务故障需用不同错误码呈现。
- **默认安全：** 不记录 Cookie、Passkey、API Key、下载器密码和完整磁力链接到日志。

## 5. 详细功能需求

### 5.1 首次启动、NAS 配对与服务连接（P0）

**目标：** 用户安装 App 后能安全连接 NAS，不需要在每个功能页重复填写 NAS 地址。

功能要求：

- 首次启动进入引导页，说明 App 需要连接自建 PT Pocket 服务。
- 支持配置 LAN 地址、WAN 地址、模式（自动 / 强制内网 / 强制外网）。
- 支持输入一次性配对码或管理员签发的设备令牌；不要将固定管理员密钥硬编码在 App。
- 测试服务健康、API 版本兼容、鉴权和数据库就绪状态。
- 自动模式优先 LAN，LAN 不通时切换 WAN；每次请求失败都能触发备用链路重试。
- 展示当前使用链路、最近成功时间、延迟和连接诊断结果。
- 用户可在设置中重新配对、撤销设备令牌和切换网络模式。

验收标准：
1. 仅配置 LAN 时可完成配对和访问；仅配置 WAN 时可完成访问；双地址时能自动择优。
2. LAN 不可用后能切换 WAN，不会把旧地址永久缓存。
3. 令牌失效时提示重新配对，不无限重试。
4. 连接诊断日志不包含令牌明文。

### 5.2 PT 站点管理（P0 基础 / P1 扩展）

**目标：** 统一维护多个 PT 站点及其授权状态。

站点卡片字段：站点名称、域名、图标、适配器类型、连接状态、最后同步时间、授权状态、已启用能力、最近错误。

功能要求：

- 添加站点：从内置站点定义库选择，或通过自定义适配器地址添加（需验证适配器兼容）。
- 支持站点凭据类型：Cookie、API Key、用户令牌，以及由站点官方流程产生的浏览器会话。Passkey 应尽量通过 Android / 浏览器原生凭据管理器使用，不将私钥作为普通文本保存。
- 凭据表单需显示字段说明、示例格式、有效期和风险提示。
- 支持连接测试、凭据更新、临时禁用、删除站点和查看适配器能力。
- 测试连接只验证最小必要接口，不执行真实下载、签到或可能扣除魔力的操作。
- 同一站点允许不同登录凭据配置，但默认对同一域名做重复实例提醒。
- 站点适配器需声明：登录类型、搜索、详情、用户数据、签到、下载链接、做种统计等能力；未声明能力的 UI 必须禁用。
- 适配器版本变更时显示变更说明；升级失败应回滚至上一个可用版本。

**CookieCloud 导入：**
- 用户配置自托管 CookieCloud 地址和访问凭据。
- 用户主动点击同步后，由 NAS 连接 CookieCloud 拉取可用 Cookie；在 App 展示可识别站点和导入预览。
- 用户选择具体站点后确认导入，冲突时支持覆盖、保留旧凭据或取消。
- 同步失败、过期 Cookie 和无法匹配的域名必须显示原因。

**CookieCloud 导入（V1.2 补充实现约束）：**
- 服务器地址支持「域名 + 反代端口 + 子路径」写法；未写协议时内网按 http、公网按 https 尝试，另一种协议与官方 `GET {基址}/get?uuid=` 形态会自动兜底再试一次。
- 响应统一按纯文本取回后自行判断，兼容 `{encrypted: ...}`、被再包一层引号的 JSON 字符串，以及直接返回密文的部署。
- 端到端加密：口令 = `md5(uuid + '-' + password)` 前 16 位；密文为 OpenSSL `Salted__` 结构，AES-256-CBC + PKCS7，解密只在本机进行。
- 失败提示必须包含实际请求地址与失败类型（HTTP 状态码 / 超时 / 域名解析 / 证书），不得只给一句“失败”。
- 地址、UUID 与端到端密码在点击「拉取并解析」后自动保存，下次进入自动回填；密码仍只存本机安全存储。
- 实现现状（V1.2）：当前由 App 直连自托管 CookieCloud 拉取并在本机解密，未经过 NAS；是否改为由 NAS 代取列入 §20.8 待确认事项。

**PTD 备份导入（V1.2 更新：直接支持 zip 备份）：**
- 直接选择 PTD 插件导出的 zip（典型成员：`config.json` / `cookies.json` / `userInfo.json` / `manifest.json` / `downloadHistory.json`），不再要求用户自行拆出单个 JSON；单个 JSON 仍可作为兼容入口。
- App 自行逐个成员识别并按「站点」合并：名称与地址取自站点配置成员，Cookie 取自 cookie 成员，API Key / Passkey 取自用户信息成员；只看域名与 Cookie 串的 `cookies.json` 也能建出站点条目。
- 识别不出站点信息的成员如实标注「已忽略」与原因，不做静默丢弃；页面列出每个成员的「已采用 / 已忽略」结果。
- 同一站点只建一条：字段冲突时保留先解析到的值并给出提示；重复导入不会重复建档。
- 展示预览、站点映射和导入结果；不得静默覆盖现有凭据。
- 导入格式仍以实际 PTD 备份样本与版本验证为准，未验证到的结构标记 TBD。
- 选文件入口实现约束（V1.2）：不引第三方文件选择插件——AGP 9 下 `file_picker` / `file_selector_android`
  改为依赖 AGP 内建 Kotlin，而本工程按 Flutter 模板关闭了内建 Kotlin，其 Kotlin 源码不会被编译
  （构建报 `cannot find symbol: FilePickerPlugin`）；改为在 app 模块用自有 MethodChannel
  `ptpocket/file_picker` 调 `ACTION_OPEN_DOCUMENT` 取回字节。桌面端暂无该通道，页面提示改用粘贴 JSON。

**Vaultwarden：**
- 提供可配置的 Vaultwarden Web Vault 地址，使用受控 WebView 打开。
- 登录、解锁和 Autofill 由用户在 Vaultwarden / Android 系统支持的流程中完成。
- PT Pocket 不读取或上传 Vaultwarden 主密码，不抓取保管库内全部密码，不将 WebView Cookie 作为站点通用凭据。
- 对外部导航、下载和文件选择进行域名白名单和用户确认控制。

验收标准：可以添加至少两个不同适配器的站点实例；站点凭据加密落库；API 读取站点配置时不返回凭据明文；站点能力缺失时相关按钮不可用并解释原因。

### 5.3 多站聚合搜索（P0 核心）

**目标：** 提供接近 PT-depiler 的高效搜索体验，首发由 NAS 聚合站点适配器和 MoviePilot V2 能力。

功能要求：

- 搜索词支持中文、英文、数字、年份和常见片名写法；后续可扩展 TMDB / IMDb ID 等结构化条件。
- 搜索请求由 App 发至 NAS；NAS 按配置的站点和 MP 实例并行查询。
- 单个站点超时或失败不阻塞其他站点，先返回成功结果；所有失败时才显示整体失败。
- 结果合并并标注来源站点、来源 MP、站点原始 ID 和适配器。
- 去重优先使用 info hash；没有 hash 时使用站点 ID + 标准化标题 + 大小等组合键，避免误删不同版本资源。
- 支持按大小、做种数、下载人数、促销、站点、发布时间、分辨率 / 编码等可用字段筛选或排序。
- 结果字段缺失时显示 `—` 或“站点未提供”，不可猜测。
- 搜索历史和收藏需可清空；收藏支持备注和标签。
- 搜索结果点击进入详情；长按弹出下载器选择器；左滑提供下载与收藏入口。
- 快速推送前必须确定目标下载器；未设置默认下载器时弹出目标选择器。
- 搜索分页和站点单独的 next cursor 由 NAS 管理，前端不得自行拼凑站点分页 URL。

搜索结果卡片建议显示：标题、站点徽标、FREE / 促销标签、体积、做种 / 下载人数、完成次数、发布时间、分辨率等。详情页显示全部可用元数据、站点原始详情入口、下载器目标、默认路径及推送结果。

验收标准：多站搜索在单站异常时仍返回其他站点结果；同 hash 结果能去重并保留全部来源；详情推送有明确进度与失败原因；快捷操作不会发生无目标推送。

### 5.4 MoviePilot 集成（P0 V2 / P2 V3）

- 支持配置多个 MP 实例，每个实例独立保存名称、**内网地址 + 外网地址**、版本、访问令牌和启用状态。
- V1.2：实例地址由单一地址升级为内网 / 外网双地址；旧数据（只有一个地址）按内网 / 公网自动归入对应通道，不丢弃用户已填地址。
- V1.2：MP 实例复用与 NAS 服务地址相同的链路策略——内网优先（2 秒探测）、失败回退外网（10 秒探测）、回到家庭网络后自动切回内网、成功选路缓存 5 分钟、网络变化或请求失败立即失效重选；配置页分别展示两条通道的探测结果与「当前生效」链路。
- 首期优先 MoviePilot V2，完成连接测试、搜索增强、可用资源查询和版本识别。
- V3 采用独立适配器，不与 V2 混用路径、数据结构或插件假设。
- MP 不可用时，PT Pocket 的原生站点搜索仍能单独工作。
- MP 返回数据需要保留源站标识和原始资源信息；聚合后由统一搜索结果模型呈现。
- 配置页显示 MP 版本兼容情况、上次成功时间、错误摘要和接口权限范围。

### 5.5 种子详情与下载推送（P0）

详情页要求：
- 显示资源名称、副标题、站点、分类、大小、促销、做种人数、下载人数、完成次数、发布时间、媒介信息和原站详情链接（以适配器实际返回为准）。
- 显示资源来源和数据更新时间，避免将缓存数据误认为实时数据。
- 支持选择已配置的下载器、分类 / 标签和保存目录。
- 默认保存路径按下载器记忆；用户可在本次推送时临时修改。
- 推送前检查下载器在线状态、目标路径格式、任务重复和站点下载链接是否过期。
- 推送流程分阶段展示：获取下载链接、校验下载器、提交任务、服务端确认。
- 成功时显示下载器名称、链路（NAS 内网 / 外网）和任务 ID；失败时保留明确失败阶段。
- 删除或取消已推送任务必须在下载器任务页执行，并明确是否同时删除本地文件。

快捷交互：
- 单击：打开详情。
- 长按：弹出下载器选择面板，选择后可直接推送；允许设置“默认快捷推送目标”。
- 左滑：下载、收藏；若只有一个默认目标，可一步推送，否则先选目标。

### 5.6 下载器管理与任务中心（P0 配置 / P1 任务）

支持多实例而不是固定每种类型一台。首期适配 qBittorrent Web API 和 Transmission RPC。

下载器配置字段：名称、类型、LAN 地址、WAN 地址、链路模式、认证方式、用户名、密码、默认路径、默认分类、是否启用、最近测试状态。

任务中心要求：
- 合并显示所有启用下载器的任务，且标注任务来源下载器。
- 筛选：全部、下载中、做种中、暂停、错误、已完成；支持按名称搜索。
- 显示名称、进度、速度、剩余时间、大小、上传 / 下载量、分享率、状态、所属下载器。
- 支持暂停、继续、强制开始、删除任务、删除文件（高风险动作二次确认）、移动分类 / 标签（若 API 支持）。
- 任务详情显示文件列表、Tracker / 状态、错误原因、保存路径和时间信息（以下载器 API 能力为准）。
- 任务操作需展示提交结果，避免把“已发送请求”误报成“已完成”。
- 支持任务刷新间隔配置；后台不应高频轮询造成 NAS 或下载器负载。

### 5.7 PT 我的数据、历程与统计（P1）

- 展示每个站点的上传量、下载量、分享率、魔力值 / 积分、等级、做种数量、做种体积、做种时间等站点实际提供的数据。
- 将一次读取保存为历史快照，形成日、周、月趋势。
- 不同站点字段含义不同，必须记录原始值、标准字段映射、单位和解析时间。
- 未提供的字段标记为不支持，不应由估算值补齐。
- 支持查看跨站总览，但总览仅聚合可换算单位相同的字段。
- 支持用户手动修正备注或输入站点无法自动获取的指标，并保留“手动录入”来源标识。

### 5.8 保号 / 养老计划（P1）

- 每个站点可建立独立规则：目标上传量、下载量、分享率、做种时间、魔力余额、等级要求或站点自定义阈值。
- 规则可设为周期目标，例如每周做种时长、每月上传量；具体指标由站点能力和用户输入决定。
- 进度显示当前值、目标值、剩余差额、截止时间和数据更新时间。
- 对可能影响账号状态的阈值设置提前提醒，不自动执行风险较高的下载、删除或刷量操作。
- 计划支持暂停、归档、调整目标和日志查询。
- 系统不保证跨站指标语义相同；对无法可靠映射的指标应分站显示。

### 5.9 PT 监护室 / 站点健康与事件（P0 接入 / P1 丰富）

- 对接 Guardian 监控服务，显示站点在线、异常、连续失败、延迟和最近检查时间。
- 适配 ptseek.pages.dev、savept.icu 等信息来源时，先确认是否存在稳定公开接口或授权数据源；无稳定接口时使用受控人工配置或外部跳转，不假设页面结构永久不变。
- 事件类型至少包括：站点不可达、持续异常、疑似风险、维护通知、站庆提醒、域名 / 入口变化。
- 每条事件必须保存来源、采集时间、有效期、置信度或来源状态；过期事件需标注“可能已过期”。
- 站点状态未知与站点正常必须严格区分。
- 支持按站点订阅通知、静音、关闭特定事件类型。

### 5.10 签到与失败补签（P1）

- 只对适配器明确支持且站点规则允许的签到方式启用。
- 用户可设置启用站点、执行时区、执行窗口和是否启用有限重试。
- 每次任务记录开始时间、请求结果、响应分类、重试次数和失败原因。
- 失败原因需要分类：网络错误、鉴权失效、站点维护、频率限制、验证码 / 二次验证、适配器解析异常。
- 验证码、人工挑战或风控触发时必须停止自动尝试并通知用户；不得通过第三方验证码服务或其他方式绕过。
- 自动补签只能在站点明确允许且任务仍处于可补签窗口内时执行；超出窗口只提示用户。
- 每个站点可单独关闭自动签到；提供“仅提醒不自动执行”模式。

### 5.11 App 网络代理与旁路由（P1）

- 支持配置 App 出站代理或自建旁路由代理服务地址，首期覆盖常见 HTTP CONNECT / SOCKS5 能力（具体实现需按 Flutter / Dio 能力验证）。
- 代理设置支持全局启用、按目标域名 / 服务选择启用，以及连通性测试。
- 代理凭据加密存储；日志隐藏用户名、密码和完整代理 URL 中的敏感段。
- 代理失败时按用户配置选择直连、停止请求或切换备用代理；默认不静默降级到不安全链路。
- NAS 服务端访问代理与手机 App 网络代理分开配置，避免误以为手机代理一定改变 NAS 的出口网络。

### 5.12 通知渠道（P1）

- 支持企业微信机器人 / 应用通知和 Telegram Bot，具体按用户配置的 Token、Chat ID 或 Webhook 方式实现。
- 通知事件：站点异常、签到失败、保号阈值、下载推送结果、任务失败、适配器失效、服务更新和备份异常。
- 支持单渠道启停、消息模板、测试消息、静默时段和重复告警抑制。
- 通知只发送必要摘要，默认不发送 Cookie、API Key、下载器密码和完整鉴权链接。

### 5.13 备份、升级与配置继承（P0 基础 / P1 完整）

- NAS 服务端定期备份数据库和必要配置；凭据密文与加密主密钥必须分别管理。
- 导出包包含 schema 版本、App 配置版本、服务端版本、导出时间和完整性校验。
- 导出是否包含加密凭据需用户明确选择；默认不导出明文。
- 恢复前执行预检、冲突检测和数据库快照；恢复失败可回滚。
- 数据库迁移必须版本化、可重复执行，并在重大迁移前备份。
- App 升级不应清空本地 NAS 地址、设备绑定信息、主题和其他用户设置。
- 服务端 API 采用向后兼容策略；移动端发现 API 版本不兼容时明确提示升级建议。
- V1.2：**所有配置表单在点击「测试连接」后自动保存**（连接与服务、站点、下载器、MoviePilot、推送通道、网络代理），无论测试成功或失败都落盘已填内容；测试结论只用于展示与健康状态，不需要用户再点一次保存。
- V1.2：同一页面重复测试复用同一条记录，不重复建档；失败原因仍完整显示在页面上。
- V1.2：新增配置键必须补齐默认值；结构性变更必须递增 `configSchemaVersion` 并登记迁移（MoviePilot 双地址使版本由 3 升至 4）。

## 7. 目标技术架构

### 7.1 架构原则

1. App 只承担交互和本地展示，不在每个页面内各自实现站点 HTTP 逻辑。
2. 站点访问、搜索并发、定时任务和通知统一由 NAS 后端调度，避免手机休眠导致任务中断。
3. 第三方系统全部通过 Adapter 接口隔离，站点差异不得泄漏到公共 UI 模型。
4. 所有服务端数据访问通过版本化 API；移动端不直连数据库或 Redis。
5. 单一 Docker Compose 部署优先，模块化边界清晰，首期不拆分微服务。

### 7.2 逻辑架构

```text
┌──────────────────────────────────────────────────────────────┐
│ 手机：HUAWEI Mate 70 Pro+ / HarmonyOS 6.1                     │
│ 目标：ArkTS + ArkUI 原生 HAP                                  │
│ 兼容轨：现有 Flutter Android APK（卓易通能力需逐项实测）      │
│ Search / Sites / Dashboard / Tasks / Secure local settings    │
└───────────────────────────┬──────────────────────────────────┘
                            │ HTTPS（LAN 优先 / Lucky WAN 备用）
                            ▼
┌──────────────────────────────────────────────────────────────┐
│ PVE 9.1.1 宿主机                                               │
│  └─ Debian 13 VM：pt-pocket-srv                                │
│      └─ Docker Compose：                                       │
│          API / Worker / Scheduler / PostgreSQL / Redis        │
│          Site Adapter / MP Adapter / Downloader Adapter      │
└───────────────────────────┬──────────────────────────────────┘
                            │ NFS（备份 / 大文件共享）
                            ▼
┌──────────────────────────────────────────────────────────────┐
│ QNAP TS-451D                                                  │
│ NAS Share / NFS / Snapshot / HBS Backup                       │
│ PostgreSQL 与 Redis 数据目录不放在 NFS                        │
└──────────────────────────────────────────────────────────────┘

PVE VM 内的业务连接：
  Site Adapters -> PT Sites      MP Adapters -> MoviePilot V2/V3
  Downloader Adapters -> qBittorrent / Transmission
  Notification -> WeCom / Telegram / 可用的手机推送通道
```

### 7.3 部署组件

| 组件 | 职责 | 备注 |
|---|---|---|
| `pt-pocket-api` | FastAPI，设备鉴权、业务 API、OpenAPI | 对 LAN / Lucky 反代暴露 |
| `pt-pocket-worker` | 搜索聚合、站点同步、下载推送、自动化执行 | 与 API 共用应用代码 |
| `pt-pocket-scheduler` | 周期性触发签到、站点状态和保号检查 | 与 Worker 分离运行，避免重复调度 |
| `postgres` | 业务数据、任务、快照、审计 | 不对公网开放端口 |
| `redis` | 缓存、任务队列、分布式锁、限流辅助 | 不对公网开放端口 |
| `backup`（可选） | 数据库与配置备份任务 | 先写入 PVE VM 本地临时目录，再复制到 TS-451D NFS 备份共享目录 |

部署目录固定为 `/data/docker-compose/pt_pocket`，建议按 `compose/`、`data/`、`backup/`、`.env`、`config/` 分层。敏感密钥应通过 Docker secrets 或受限权限文件注入，不进入 Git 仓库。

### 7.4 客户端与服务端职责边界

| 能力 | 默认执行端 | 可选例外 |
|---|---|---|
| PT 站点登录态、搜索、用户数据 | NAS | 仅在明确支持且用户主动开启的场景使用手机浏览器交互 |
| 搜索聚合和去重 | NAS | 无 |
| MoviePilot 连接 | NAS | 无 |
| 签到、补签、保号检查 | NAS Worker | App 负责审批 / 人工挑战 |
| 下载器推送和任务同步 | NAS | 用户可显式启用手机直连下载器，但默认关闭 |
| 本地通知展示 | Android | NAS 负责事件生成和通知渠道发送 |
| Vaultwarden WebView / Autofill | Android | 不把主密码提交给 NAS |
| LAN / WAN 服务寻址 | Android | 可手动覆盖调试 |

### 7.5 网络链路策略

- App 连接 NAS 的地址由 Endpoint Manager 统一管理。
- 自动模式按网络环境优先 LAN，失败后切换 WAN；网络切换事件应立即清理旧缓存。
- 对 WAN 地址强制 HTTPS；拒绝证书错误和不安全重定向。
- 健康探测应检查 API 健康状态，而不是只以 TCP 可连接判定可用。
- 连接失败重试需使用退避和请求幂等保护；下载推送等写操作必须携带幂等键，防止链路切换重复创建任务。
- NAS 到下载器的连接优先使用 NAS 内网地址；外网反代只作为用户远程控制 NAS API 的通道，不代表下载器本身需要暴露公网。
- V1.2：Android release 包必须声明 `INTERNET` 与 `ACCESS_NETWORK_STATE`，并允许访问内网明文（http）自建服务（`usesCleartextTraffic`）。release 只合并 `main` 清单，缺权限会让全部出网请求表现成“不可达 / 域名解析失败”，验收时必须直接核验已构建 APK 的清单。
- V1.2：地址归一化统一处理「无协议 / 带端口 / 反代子路径」三种写法；拼接 API 路径必须保留基址子路径，不能用 `Uri.resolve` 丢掉它；带空白的非法地址直接拒绝，不做百分号编码兜底。
- V1.2：可用性判定分三档呈现——可用（2xx 且为 JSON 健康响应）/ 地址可达但后端未就绪（拿到 HTTP 但非 2xx，或 2xx 但不是本服务的 JSON）/ 不可达（网络层失败），并显示实际请求地址与失败类型。

### 7.6 站点 Adapter 设计

每个适配器至少声明：

- `adapter_id`、版本、支持站点类型和兼容版本；
- 认证方式和凭据 Schema；
- `test_connection`、`search`、`get_torrent_detail`、`get_user_stats`、`sign_in` 等能力函数；
- 速率限制、默认超时、重试策略和错误映射；
- 是否支持自动签到、是否需要用户确认、是否支持下载链接生成；
- 输出统一 DTO，同时保留必要的站点原始字段。

Adapter 不允许通过不受控动态代码执行扩展。首期采用受信任内置 Python 模块和版本化配置；未来插件机制须有签名、权限声明、网络访问边界和审计记录。

### 7.7 物理部署规划：PVE 计算 + QNAP 存储

#### 7.7.1 PVE 宿主与虚拟机

- PVE 9.1.1 作为虚拟化宿主，不直接承载 PT Pocket 的 Docker 应用栈。
- 创建独立 VM：`pt-pocket-srv`，建议使用 Debian 13（与 PVE 9 系列基础系统代际一致），启用 QEMU Guest Agent，配置固定 DHCP 租约或静态地址。
- Docker Engine 与 Compose Plugin 安装在 VM 内；应用目录为 `/data/docker-compose/pt_pocket`。
- VM 系统盘与 Docker 数据盘使用 PVE 本地 SSD / NVMe 存储池；不要把 PostgreSQL 的 WAL 和数据目录直接放在 QNAP NFS 上。
- 若 PVE 主机已有其他 VM / LXC，应按主机实际余量分配 CPU 和内存，避免过度承诺 vCPU 或 RAM。

#### 7.7.2 QNAP 共享目录建议

建议在 TS-451D 创建独立共享目录，按职责拆分权限：

| 共享目录 | 用途 | 挂载建议 |
|---|---|---|
| `pt-pocket-backup` | PostgreSQL 逻辑备份、配置备份、恢复包 | Debian VM 内 NFS 挂载，专用账号可写 |
| `pt-pocket-export` | 用户主动导出的 PTD / 配置包 / 报表 | NFS 或 SMB，按需挂载 |
| `downloads`（若现有下载器使用） | 下载器保存数据 | 按现有下载器的宿主路径与容器路径统一映射 |
| `media`（可选） | MoviePilot 媒体库 / 媒体整理结果 | 由 MP 和下载器保持同一映射规则 |

NFS 只开放给 PVE Debian VM 的固定地址或受控网段；关闭匿名写入；避免把整个 NAS 根目录授权给容器。备份共享目录应与日常下载目录分开，降低误删风险。

#### 7.7.3 推荐容器编排

```text
/data/docker-compose/pt_pocket/
├── docker-compose.yml
├── .env                  # 不进 Git；权限 0600
├── config/               # 非机密应用配置
├── data/                 # VM 本地 SSD：postgres / redis
├── logs/                 # 日志滚动目录
├── backup-staging/       # 本地临时备份目录
└── scripts/              # 备份、恢复、升级脚本

/mnt/qnap/pt-pocket-backup/  # NFS：最终备份副本
/mnt/qnap/downloads/         # 可选：下载器共同路径
/mnt/qnap/media/             # 可选：媒体库路径
```

#### 7.7.4 网络和反向代理

- 为 QNAP、PVE 宿主和 Debian VM 配置 DHCP 保留地址；建议有线千兆连接，不将 PT Pocket 关键服务依赖于 Wi-Fi。
- 若路由器支持分流 DNS，优先使用同一个 HTTPS 域名：内网 DNS 解析至 Debian VM 私网地址，外网 DNS 指向 Lucky 反向代理入口（Split-horizon DNS）。
- 若暂不具备分流 DNS，则 App 配置 LAN 与 WAN 两个 API Endpoint，由 Endpoint Manager 主动健康检查、切换并对写操作使用 Idempotency-Key。
- Lucky 只反代 PT Pocket API（必要时包括 WebSocket）；PostgreSQL、Redis、Docker API、SSH 和下载器管理端口不对公网开放。
- WAN 强制 HTTPS、有效证书、访问控制、限速和审计；不得使用关闭 TLS 校验或全局允许明文 HTTP 的方式解决证书问题。
- NAS 到下载器尽量走家庭内网，手机远程访问只需打到 Lucky 的 PT Pocket API 入口，不需要把 qB / Transmission 暴露到公网。

### 7.8 资源配置建议（待 PVE 主机参数复核）

| 配置档位 | VM vCPU | VM 内存 | 系统 / 应用盘 | 适用范围 |
|---|---:|---:|---:|---|
| 最低试运行 | 2 核 | 4GB | 32–40GB SSD | Phase 1、低并发、少量站点适配；不宜同时跑重型 MP / 媒体任务 |
| 推荐起步 | 4 核 | 8GB | 64–100GB SSD | API、Worker、PostgreSQL、Redis、多个站点适配器及常规搜索 |
| 有余量时 | 4–6 核 | 8–12GB | 100GB+ SSD | 增加搜索并发、更多站点、多个 MP 实例及更长历史快照 |

上述为 PT Pocket VM 的建议额度，不代表 PVE 主机当前具备这些资源。最终配置必须以 `lscpu`、`free -h`、`lsblk`、`pvesh get /nodes/{node}/status` 和现有虚拟机负载为依据。若主机资源不足，优先降低 Worker 并发、搜索超时和快照保留量，不要把数据库迁回 TS-451D 来“省资源”。

### 7.9 手机端平台策略：Flutter Android + HarmonyOS 原生

| 轨道 | 技术 | 目标 | 交付要求 |
|---|---|---|---|
| Android 通用版 | 现有 Flutter / Dart | 覆盖标准 Android 用户，保留已有 UI 和业务代码 | 正常 APK / AAB 构建，CI、签名、Android 真机测试 |
| Mate 70 Pro+ 兼容验证 | Flutter Android APK 经 HarmonyOS 兼容环境安装 | 尽量复用当前原型，降低短期迁移成本 | 安装、启动、网络、安全存储、WebView、通知、手势等关键用例通过后才可作为可选安装包 |
| HarmonyOS 正式适配轨 | ArkTS + ArkUI + Stage 模型，HAP/APP 包 | 提供 HarmonyOS 6.1 原生系统体验和长期维护能力 | 使用 DevEco Studio 构建、签名，在 Mate 70 Pro+ 真机验收系统能力和权限 |
| 临时访问兜底 | NAS 提供响应式 Web / PWA（可选） | 原生端开发期间提供基本远程管理入口 | 不持有长期站点凭据；仍通过 NAS API；能力少于原生端 |

鸿蒙原生版与 Flutter 版共享：OpenAPI 契约、错误码、数据模型、设计 token、交互规格和测试用例。不得通过复制 Flutter 插件名来推定 ArkTS 能力等价。

### 7.10 运行时职责与故障边界

- PVE VM 停机：手机显示 NAS 不可达；不得展示旧缓存为实时状态；恢复后重新拉取服务端真实状态。
- QNAP 暂时不可达：API、搜索和数据库仍可运行；备份任务进入失败/待重试状态，不阻塞核心服务。
- QNAP 磁盘空间不足：停止写入备份并告警，不得覆盖最近一份有效备份。
- PVE VM 磁盘空间不足：停止新建历史快照和非必要日志，保护 PostgreSQL 可用空间；发出告警。
- WAN/Lucky 不可用：家庭内网服务继续可用；App 在 LAN 下仍可访问。
- 某个 PT 站点或 MP 不可用：只影响对应 Adapter，不能导致整个 API 或搜索系统崩溃。

## 8. 数据库设计（逻辑模型）

### 8.1 通用约定

- 主键使用 UUID；业务外部 ID 单独保存，不以外部 ID 作为数据库主键。
- 时间统一保存 UTC `timestamptz`，展示时按用户时区转换。
- 通用字段：`id`、`created_at`、`updated_at`；可软删除的记录额外包含 `deleted_at`。
- 所有凭据字段保存加密后的密文、密钥版本和 nonce / tag 等元信息；禁止保存明文。
- 搜索结果保留来源站点和适配器版本，便于问题追踪。

### 8.2 核心表

| 表名 | 主要字段 | 用途 / 约束 |
|---|---|---|
| `users` | `id, username, password_hash, timezone, status` | 首期单管理员用户；未来多用户扩展 |
| `devices` | `id, user_id, device_name, platform, token_hash, last_seen_at, revoked_at` | 设备配对、刷新令牌撤销 |

| `site_definitions` | `id, site_key, display_name, base_url, adapter_id, adapter_version, capabilities_json, enabled` | 内置站点模板与能力声明 |
| `site_instances` | `id, user_id, definition_id, alias, base_url, enabled, status, last_checked_at` | 用户实际添加的站点实例 |
| `site_credentials` | `id, site_instance_id, credential_type, ciphertext, key_version, expires_at, updated_at` | 一站点多种授权材料的加密存储；`site_instance_id` 建索引 |

| `retention_checkpoints` | `id, policy_id, checked_at, current_json, target_json, status` | 保号进度历史 |

| `notification_channels` | `id, channel_type, enabled, config_ciphertext, quiet_hours_json` | 企业微信 / Telegram 配置 |
| `notification_events` | `id, event_type, payload_json, dedupe_key, created_at` | 待发送通知与去重 |
| `notification_deliveries` | `id, event_id, channel_id, status, sent_at, error_code` | 发送结果 |
| `audit_events` | `id, actor_id, device_id, action, target_type, target_id, result, redacted_detail_json` | 凭据、配置、任务操作审计；字段脱敏 |

### 8.3 关键关系

- 一个 `user` 可拥有多个 `device`、`site_instance`、`mp_instance` 和 `downloader`。
- 一个 `site_definition` 可被多个 `site_instance` 引用。
- 一个 `site_instance` 对应一个或多个加密凭据条目、多个统计快照、多个保号计划和多个站点事件。
- 一个 `search_session` 关联多个 `search_results`；一个 `torrent_item` 可来自多个搜索来源。
- 一个 `automation_job` 对应多次 `automation_runs`。
- 一个 `notification_event` 可向多个 `notification_channels` 投递。

### 8.4 索引与保留策略

- `site_instances(user_id, enabled)`、`site_events(site_instance_id, occurred_at DESC)`、`site_stats_snapshots(site_instance_id, captured_at DESC)` 建复合索引。
- `torrent_items(site_instance_id, external_torrent_id)` 唯一索引；`info_hash` 采用可空索引。
- `search_results(search_session_id, rank)` 建索引；搜索会话及结果按配置保留期限清理。
- `automation_runs(job_id, started_at DESC)`、`notification_deliveries(status, sent_at)` 建索引。
- 审计事件按安全策略长期保留或滚动归档；密钥和认证材料从不写入审计明细。
- 下载器任务快照采用可配置窗口，避免长期保存高频无价值数据。

## 9. API 规范（REST / JSON）

### 9.1 通用规范

- Base Path：`/api/v1`。
- 编码：UTF-8 JSON；时间使用 ISO 8601 UTC。
- 鉴权：`Authorization: Bearer <access_token>`；刷新令牌只在明确的刷新接口使用。
- 所有写操作对可重试请求支持 `Idempotency-Key`。
- 分页统一使用 `page` / `page_size` 或 cursor；推荐搜索结果使用 cursor。
- API 返回统一错误结构，业务层不得直接把第三方原始响应全文返回客户端。

标准成功响应：

```json
{
  "data": {},
  "meta": {
    "request_id": "uuid",
    "server_time": "2026-11-03T12:00:00Z"
  }
}
```

标准错误响应：

```json
{
  "error": {
    "code": "SITE_CREDENTIAL_EXPIRED",
    "message": "站点授权已失效，请更新凭据",
    "retryable": false,
    "details": {}
  },
  "meta": {
    "request_id": "uuid"

}
```

### 9.5 错误码建议

| 错误码 | 含义 | 客户端行为 |
|---|---|---|
| `AUTH_REQUIRED` | 未认证 | 引导重新配对 / 登录 |
| `AUTH_EXPIRED` | 访问令牌失效 | 刷新一次，失败后重新配对 |
| `SITE_CREDENTIAL_EXPIRED` | 站点凭据失效 | 定位至凭据管理 |
| `SITE_RATE_LIMITED` | 站点限流 | 显示重试时间，不立即重试 |
| `SITE_CHALLENGE_REQUIRED` | 验证码 / 人工验证 | 停止自动化并提示人工处理 |
| `ADAPTER_UNSUPPORTED` | 适配器不支持此功能 | 禁用相关动作并展示原因 |
| `DOWNLOADER_UNAVAILABLE` | 下载器不可达 | 检查链路和凭据 |
| `DUPLICATE_TASK` | 任务疑似重复 | 展示已有任务并让用户决定 |
| `IDEMPOTENCY_CONFLICT` | 幂等键冲突 | 返回原操作状态，不重复执行 |
| `UPSTREAM_TIMEOUT` | 第三方服务超时 | 允许有限退避重试 |
| `INTEGRATION_VERSION_UNSUPPORTED` | MP / 外部服务版本不兼容 | 提示适配器版本状态 |

## 10. 安全、隐私与站点规则

### 10.1 凭据保护

- NAS 端凭据采用信封加密：数据库仅保存密文，主密钥由 Docker secrets 或宿主机受限文件提供。
- 每种凭据保留 `key_version`，支持加密密钥轮换。
- API 只允许写入或轮换凭据，不提供明文读取接口；需要查看时以“已设置 / 未设置 / 即将过期”呈现。
- 手机端只保存 NAS 访问令牌、LAN/WAN 地址和用户明确选择的本地配置；下载器和 PT 凭据默认不再长期保存在手机。
- 日志、异常堆栈、通知、诊断包必须过滤 Cookie、API Key、Passkey、下载器密码、磁力链接中的敏感令牌。

### 10.2 网络与服务安全

- 外网入口使用 HTTPS；反向代理只公开 API 所需端口。
- PostgreSQL、Redis 不映射公网端口；Worker 与 Scheduler 不提供公网管理端口。
- 设置请求体大小限制、速率限制、连接超时、读取超时和域名 / IP 访问策略。
- 对用户输入的 URL、下载器地址和代理地址进行协议、端口、DNS 解析及内网访问边界验证，防止 SSRF 和 DNS 重绑定。
- 禁止自动跟随跨域重定向携带鉴权头；第三方请求不得默认复用 NAS 管理端鉴权信息。
- 管理令牌采用短期访问令牌和可撤销设备刷新令牌，不用单一永久 Token 作为生产认证。

### 10.3 站点规则与自动化边界

- 自动化必须尊重站点公开规则、API 限制和访问频率。
- 站点要求验证码、二次验证或人工确认时终止自动流程。
- 不通过更换身份、伪装流量或外部破解服务绕过访问限制。
- 站点适配器记录请求频率和失败类型，防止故障重试造成请求风暴。
- 用户可随时关闭单站点所有后台任务。

### 11.1 结合个人硬件的非功能指标

- Phase 1 在最低试运行 VM 档位（2 vCPU / 4GB RAM）下应能够稳定完成健康检查、设备配对、站点 CRUD 和基础连接测试。
- 推荐起步 VM 档位下，API 常规读请求 P95 目标低于 500ms（不含第三方 PT 站点响应）；数据库和 Redis 均不经公网访问。
- 单站搜索超时不得拖死整个请求；并发数、每站超时、总时限和 Worker 队列长度均可配置。
- 应用服务与数据必须可独立备份；每次正式版本升级前自动生成 DB 备份并记录 Alembic 版本。
- QNAP NFS 不可用时，核心 API / 数据库仍应保持运行；只暂停依赖共享目录的备份和文件导入导出任务。
- Mate 70 Pro+ 是 P0 真机回归设备；模拟器测试不能替代鸿蒙系统兼容层、权限和后台行为验证。

## 15. AI Agent 工作流与质量门禁

### 15.1 Agent 角色

| Agent | 职责 | 主要产出 |

| Backend Agent | FastAPI、数据库、Worker、Adapter | API、迁移、后端测试 |
| Mobile Agent | Flutter 页面、状态管理、API 调用 | Android UI、集成测试 |

| Security Agent | 凭据、URL、日志、访问控制审查 | 安全审查意见和修复清单 |
| DevOps Agent | Docker、CI、备份、升级 | Compose、工作流、部署手册 |

### 15.2 标准开发流水线

1. Product Agent 将需求拆为可验收 User Story，并标注 P0 / P1 / P2。
2. Architect Agent 先确定数据结构、API 契约、错误码和边界，不允许 UI 与 Backend 各自臆造字段。
3. UI/UX Agent 输出页面状态和交互流程，至少覆盖加载、空、错误、部分成功和禁用态。
4. Backend / Mobile Agent 按契约并行实现，提交前更新 OpenAPI / Schema。
5. QA Agent 执行单元、契约、集成和 UI 测试；Security Agent 审查凭据、日志、代理与 URL。
6. DevOps Agent 验证 Docker 构建、迁移、健康检查、备份恢复和升级继承。
7. 合并前必须通过质量门禁；涉及凭据、签到和删除操作的改动必须人工复核。

### 15.3 Definition of Done

- 需求有明确验收条件且实现与验收条件一致。
- API、数据库迁移、日志和错误码已更新。
- 自动化测试通过；新增代码有必要测试覆盖。
- 凭据不明文保存、不回显、不进入日志。
- Android / Docker 构建通过；关键路径在实际设备或 NAS 环境验证。
- 更新用户文档、部署文档和版本变更记录。
- V1.2：构建 / 打包 / 发版前已重读 `docs/需求规格书.md`；本轮行为变更已同时回写到规格书与 `README.md`。

## 17. 风险、依赖与待确认事项

### 17.1 主要风险

- **站点接口变化：** 每个站点可能改变登录、搜索或字段结构；必须建立适配器版本和契约测试。
- **站点规则风险：** 自动签到和重试可能被视为异常行为；默认保守、限频、人工挑战停止。
- **外网暴露风险：** Lucky 反代一旦错误暴露管理接口可能泄露凭据；必须 HTTPS、认证、访问控制和日志审计。
- **加密密钥丢失：** 数据库密文不能单独恢复；需要明确的密钥备份流程和恢复演练。
- **多来源数据质量：** MP 与站点返回的字段可能冲突；必须保留 source 和更新时间。
- **NAS 资源限制：** CPU / RAM / 存储和 Docker 兼容性影响 Worker 并发、数据库和搜索响应。

### 17.2 待确认事项

1. PVE 自组主机 CPU 型号、线程数、内存总量、SSD/NVMe 容量、存储池和网卡速率；用于确定 Debian VM 最终配额。
2. TS-451D 当前实际内存（4GB / 8GB）、QTS 版本、磁盘 RAID / 卷结构、NFS 是否已启用。
3. Lucky 反代的域名 / TLS 证书形态、家庭路由是否支持分流 DNS；只需描述拓扑，不需要分享域名令牌或密码。
4. qBittorrent / Transmission、MoviePilot V2 的部署位置、实例数量、API 版本及路径映射。
5. 首批 PT 站点名单、12 个重点站点名单，以及“收集进度”的统计口径。
6. Mate 70 Pro+ 上是否安装卓易通、是否愿意通过 DevEco Studio / 测试签名安装自建 HAP；不需要提供华为账号密码或设备识别码。
7. Guardian、ptseek、savept 的现有部署形态或可用接口样本。
8. 是否需要多台 HarmonyOS / Android 设备共享同一 NAS 管理账号。

## 18. 本次审查结论与实施建议

上传的 ZIP 已经形成可运行方向的 Flutter 原型：M-Team 搜索、资源详情、收藏、基础推送、qB / TR 配置和 Guardian 状态展示具有可复用价值。它不应被推倒重来，但也不宜继续在现有“手机直连所有服务”的模式上无限叠加功能。

建议采用“保留 Flutter UI 资产、重构网络与数据边界、新增 NAS 后端”的演进路径：

1. 先做 Phase 0 / Phase 1：在 PVE 上建立 Debian 13 VM，打牢 Docker、服务端、认证、数据库、凭据加密和双链路，并将 QNAP NFS 备份跑通。
2. 将 M-Team 搜索迁移为第一个 Site Adapter，先完整跑通 App → NAS → M-Team → 结果展示。
3. 将 qB / TR 客户端迁移为 NAS Downloader Adapter，随后加入任务列表与操作。
4. 再扩展更多 PT 站点、MoviePilot V2、用户统计和 Guardian 事件。
5. 同步开展 Mate 70 Pro+ 的 Flutter APK 兼容性验证与 ArkTS 原生 HAP PoC；长期鸿蒙正式版以原生适配结果为准。
6. 最后推进自动签到、补签、通知、代理、保号和其他增强功能。

**项目当前状态判断：** 这是一个已有 Flutter 客户端代码的早期原型，不是已完成的 PT 一站式 App，也不是已部署好的 NAS Hybrid 产品。本规格书可作为下一阶段 PRD 与开发验收基线；具体站点适配、PTD 文件格式和外部监护信息源仍需真实样本验证。

## 19. 本地部署实施蓝图（V1.1 新增）

### 19.1 推荐部署位置总表

| 服务 / 数据 | 运行 / 存放位置 | 原因 |
|---|---|---|
| PVE Hypervisor | 自组设备物理机 | 负责 VM 生命周期和硬件资源 |
| Debian 13 `pt-pocket-srv` | PVE 虚拟机 | 隔离 Docker 依赖，方便备份和回滚 |
| FastAPI / Worker / Scheduler | Debian VM Docker | 需要长时间运行、稳定网络和较多并发 |
| PostgreSQL / Redis | Debian VM 本地 SSD 卷 | 降低 NFS 延迟与断连对数据库的风险 |
| 配置导出 / DB 备份副本 | TS-451D NFS 共享目录 | 利用 NAS 快照、HBS 和集中存储 |
| 下载文件 / 媒体库 | 按现有 qB / TR / MP 位置决定，可在 TS-451D | 保持下载器与 MP 路径映射一致 |
| Lucky 反向代理 | 按现有网络部署，不假定在 PVE 或 QNAP | 对外只暴露 API HTTPS 入口 |

### 19.2 首次部署步骤

1. 在 PVE 创建 Debian 13 VM，设置固定地址、QEMU Guest Agent、开机自启和合理资源上限。
2. 在 Debian VM 安装 Docker Engine 与 Compose Plugin；建立 `/data/docker-compose/pt_pocket`，限制目录权限。
3. 在 TS-451D 创建 `pt-pocket-backup` 独立共享目录，配置 NFS 允许客户端为 Debian VM 私网 IP；在 VM 内验证写入、读回和断线恢复。
4. 将 PostgreSQL / Redis 卷放在 VM 本地 SSD；配置 `.env`、加密主密钥和设备配对初始密钥，密钥不进 Git。
5. 启动 Compose，检查 `/health/live`、`/health/ready`、Alembic migration、日志脱敏和重启策略。
6. 配置数据库每日逻辑备份到本地临时目录，并异步复制到 QNAP；保留多个时间点，不覆盖最近一份已验证备份。
7. 配置 Lucky HTTPS 反代，只转发 API 域名和端口；从蜂窝网络验证访问，从公网扫描确认 DB、Redis、SSH、下载器 Web UI 未暴露。
8. App 配置 LAN/WAN 两地址并完成配对；验证切网、失败重试、写操作幂等及设备令牌撤销。
9. 最后迁移 M-Team Adapter、下载器 Adapter；不要在后端稳定前批量导入全部站点 Cookie。

### 19.3 备份策略建议

- PostgreSQL：每日 `pg_dump`，保留最近 7 份日备份及 4 份周备份；重要升级前额外备份。
- 配置：每日归档非机密配置；凭据密文与加密主密钥分开管理。主密钥必须另行离线保管，不能只备份在同一 NAS。
- PVE VM：使用 PVE 备份任务定期备份整个 VM 到 NAS 共享存储或其他独立备份介质。
- NAS：对 `pt-pocket-backup` 启用快照 / HBS（若现有卷与授权支持），并定期抽样恢复。快照不是异地备份。
- 恢复演练：至少每个大版本做一次“新 VM + 空数据库 + 备份恢复”的实测；记录所需密钥、恢复步骤和耗时。

## 20. 本轮迭代变更（V1.2：实机反馈与实现进展）

本轮依据 `v0.7.0` release APK 的实机反馈完成 5 项可用性修复 + 1 条协作规则，全部改动已入库并纳入门禁
（`flutter analyze` 无错误、`flutter test` 全部通过）。

### 20.1 统一根因：release 包没有网络权限

拆开实机安装的 `v0.7.0` APK 核对其清单，`android.permission.INTERNET` 出现次数为 **0**，也没有
`usesCleartextTraffic`。release 包只合并 `main` 清单，而 `main/AndroidManifest.xml` 从未声明网络权限
（只有 debug / profile 清单声明过），于是 App 全部出网请求失败，表现为 “Failed host lookup”“不可达”“异常”。

> 结论：反代地址判为不可达、下载器异常、CookieCloud 拉取失败、MP 不可达是同一个根因的不同表现，
> 不是地址填错，也不是密码不对。

修正与验收：
- `main/AndroidManifest.xml` 补 `INTERNET`、`ACCESS_NETWORK_STATE` 与 `android:usesCleartextTraffic="true"`；
- 验收改为「拆开 release APK 核验清单权限」，不再只看源码。

### 20.2 地址归一化与链路诊断

- 统一地址归一化：无协议时内网主机补 http、公网主机补 https；保留显式端口与反代子路径；
  丢弃 query / fragment；拒绝把 `not a host` 这类输入百分号编码后当合法地址用。
- 健康探测改为拼接而非 `Uri.resolve`，保留基址子路径（`https://h:5888/ptp` + `/api/v1/health`）。
- 可用性分三档：可用 / 地址可达但后端未就绪 / 不可达，并显示实际请求地址与失败类型。
- 2xx 但响应不是 JSON 时标记为“可能反代到了其它服务”，不作为可用链路。

### 20.3 PTD 备份改为 zip 导入

- 直接选择 PTD 插件导出的 zip，App 逐个成员识别并按站点合并（名称 / 地址 / Cookie / API Key / Passkey 分属不同成员）。
- `manifest.json`、`downloadHistory.json` 等识别不出站点信息的成员标注「已忽略」与原因；
  `{"域名": "cookie 串"}` 形式的 `cookies.json` 也能建出站点条目。
- 同一站点只建一条，字段冲突保留先解析到的值并提示；重复导入不重复建档。
- 选文件入口用 app 模块自带的 MethodChannel（`ptpocket/file_picker`）实现，不引第三方选择器插件：
  AGP 9 下 `file_picker` / `file_selector_android` 都改为依赖 AGP 内建 Kotlin，而本工程按 Flutter 模板
  关闭了内建 Kotlin（`android.builtInKotlin=false`），它们的 Kotlin 源码不会被任何一方编译，
  构建直接失败（`cannot find symbol: class FilePickerPlugin`）；宿主模块的 Kotlin 由 Flutter 的
  Gradle 插件编译，放在那里最稳。桌面端暂无该通道，页面提示改用粘贴 JSON。

### 20.4 MoviePilot 内外网双地址

- 实例由单一地址升级为内网 + 外网双地址；旧数据按内网 / 公网自动归位。
- 复用与 NAS 服务相同的选路策略（内网优先 2 秒 / 失败回退外网 10 秒 / 网络变化立即失效重选 / 缓存 5 分钟），
  配置页展示两条通道结果与当前生效链路。

### 20.5 测试后自动保存

- 连接与服务、站点、下载器、MoviePilot、推送通道、网络代理：点「测试连接 / 发送测试消息 / 测试代理」后
  自动落盘已填内容，成功与失败都保存。
- 重复测试复用同一条记录；测试结果同时写入健康状态，失败原因仍在页面显示。

### 20.6 CookieCloud 拉取修复

- 地址支持「域名 + 反代端口 + 子路径」；未写协议时按内网 http / 公网 https 猜测，并用另一种协议与官方
  `?uuid=` 形态兜底。
- 响应按纯文本取回后自行判断，兼容 `{encrypted: ...}`、被再包一层引号的 JSON、直接返回密文的部署。
- 失败时汇总每条尝试的地址与原因（HTTP 状态 / 连接类型）。
- 地址、UUID、密码自动保存并在下次进入回填（密码仍在安全存储）。

### 20.7 协作规则

- 新增第一条硬性规则：**构建 / 打包 / 发版前必须重新通读一遍需求规格书**；`README.md` 第一条同步写明。
- 规格书入库为 `docs/需求规格书.md`，与 `README.md` 一并作为验收基线。

### 20.8 本轮待确认

1. CookieCloud 拉取目前由 App 直连自托管服务并在本机解密（§5.2 原文设想由 NAS 代取）；是否改为 NAS 代取待确认。
2. 下载器与站点的第三方协议调用仍应落在 NAS 后端适配器；后端尚未实现，因此下载器任务列表等页面在真机上仍无数据。
3. release 包当前使用 debug 签名（个人直装可用）；是否配置正式 keystore 待确认。
4. Mate 70 Pro+ 若为 HarmonyOS NEXT（纯鸿蒙）则无法安装 APK，需走 HarmonyOS 原生轨道。
